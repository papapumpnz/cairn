# WP00 — Repository, operating law, constraint checker, and CI

## Objective

Create the enforceable project boundary before any inference code exists.

## Dependencies

None

## Owned scope

workspace root, `cairn-check`, CI configuration, `LAW.md`, architecture-decision-record template

## Inputs

This handoff bundle, the archived SCEM checker patterns, and the CPU/transformer rules in the master design.

## Deliverables

A compilable Rust workspace, machine-enforced policy checks, CI jobs, reproducible toolchain pinning, and self-tests that prove each prohibition fires.

## Required design

Implement a source and dependency scanner over Cargo metadata, lockfiles, build scripts, native link flags, feature selections, configuration, and production source. Detect accelerator stacks, transformer libraries, remote model APIs in the answer path, ARC task-ID literals, evaluation-path imports, forbidden crate dependency directions, and unsafe code outside allowlisted modules. Add a runtime attestation helper that records CPU, memory, process tree, loaded native libraries, network state, and environment variables. Define architecture layers in a checked dependency manifest rather than relying on documentation alone.

## Public API obligations

`cairn-check --path <repo>`, `cairn-attest --out <json>`, a library API returning structured violations, and an ADR template with status, context, decision, rejected alternatives, and compatibility impact.

## Test plan

Plant one violation for every rule in isolated fixtures. Include indirect transitive dependency, feature-activated GPU library, generated source task ID, hidden evaluation path, protocol downgrade, and forbidden import direction. CI must demonstrate fail then pass behavior without mutating the main workspace.

## Acceptance criteria

Clean workspace passes; all planted violations fail with stable machine-readable codes; checker runtime below 5 s on the repository; runtime attestation schema validates; CI runs formatting, clippy with warnings denied, unit tests, policy check, and artifact-schema validation.

## Forbidden shortcuts

Do not implement policy as grep-only. Do not block generic words such as `attention`; inspect actual dependency and source semantics. Do not let test-only fixtures trigger production failures.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
