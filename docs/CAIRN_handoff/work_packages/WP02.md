# WP02 — Packed grid representation and CPU geometry kernels

## Objective

Deliver the exact high-throughput finite-grid substrate used by all static and frame-based frontends.

## Dependencies

WP00

## Owned scope

`cairn-grid`

## Inputs

ARC grid constraints and reference semantics from the master design.

## Deliverables

Packed color grids, bitplanes, cell sets, transforms, connected components, geometry, rasterization, overlay, and naive references.

## Required design

Use specialized fixed bitsets for up to 32 by 32 and 64 by 64, with dynamic tiled storage beyond. Cache per-color bitplanes lazily. Implement D4 transforms, translation, crop, pad, integer scale, component labeling under 4/8 connectivity, contours, holes, bounding boxes, line/ray/rectangle rasterization, set morphology, distance transforms, shape signatures, and conflict-aware rendering. SIMD is optional behind audited feature detection; scalar semantics are authoritative.

## Public API obligations

`Grid`, `CellSet`, `BitGrid`, `Transform2`, `ComponentIndex`, `RendererKernel`, exact coordinate conversions, and iterator-free bulk operations where possible.

## Test plan

Exhaustive all binary grids through 4 by 4 for topology operations; exhaustive transform group laws; randomized comparison to `Vec<Vec<_>>` reference for 100,000 grids; overlay conflict cases; zero/one-cell dimensions; maximal ARC dimensions; endian round trips; fuzz malformed packed data.

## Acceptance criteria

All reference comparisons pass; component labeling median below 3 microseconds on representative 30 by 30 grids; common bitset operations above 20 million operations per core per second; no unsafe outside `simd` and packed-copy modules; benchmark variance recorded.

## Forbidden shortcuts

Do not assign semantic meaning to colors. Do not merge geometry and ARC task logic. Do not optimize before reference tests exist.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
