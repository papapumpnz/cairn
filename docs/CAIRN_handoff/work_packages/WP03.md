# WP03 — Relational Evidence Graph and query indexes

## Objective

Implement the typed attributed hypergraph that holds observations, entities, relations, events, roles, and derivations efficiently.

## Dependencies

WP01, WP02

## Owned scope

`cairn-reg`

## Inputs

Node, relation, and derivation contracts from the interfaces document.

## Deliverables

Arena-based REG, specialized relation indexes, snapshots, deterministic query engine, and artifact serialization.

## Required design

Store nodes and edges in structure-of-arrays arenas. Give common binary relations compressed adjacency bitsets and uncommon hyperedges compact argument slabs. Implement typed indexes by relation and argument position, value-column indexes, entity-to-cell membership, temporal indexes, and derivation lookup. Queries are conjunctive relation joins with filters, bounded paths, aggregates, and stable ordering. Add immutable snapshots and append-only builders so agents can share a base graph safely.

## Public API obligations

`RelGraph`, `RelGraphBuilder`, `RelGraphSnapshot`, `QueryPlan`, `RelationIndex`, `FactRef`, `DerivationArena`, and batch query result columns.

## Test plan

Random graph comparison against a simple relational reference; conjunctive join correctness; hyperedge argument ordering; snapshot isolation; concurrent readers; canonical serialization; invalid relation arity; path-bound enforcement; deterministic result order.

## Acceptance criteria

At least 10 million indexed binary-relation probes per second on baseline CPU; common two-join query under 50 microseconds on ARC-sized graphs; memory below 20 MB for a deliberately overcomplete 30 by 30 evidence graph; all graph artifacts round-trip canonically.

## Forbidden shortcuts

Do not embed a general external graph database. Do not let query plans depend on hash-map iteration. Do not mutate published snapshots.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
