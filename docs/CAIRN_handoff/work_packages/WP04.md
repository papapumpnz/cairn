# WP04 — Relational Kernel Language types, AST, bounds, and canonical form

## Objective

Define a small universal bounded relational language with explicit types and totality rules.

## Dependencies

WP01

## Owned scope

`cairn-rkl`

## Inputs

RKL specification in the master design.

## Deliverables

Typed AST, parser for debug fixtures, type checker, range and collection-bound inference, alpha-normalization, semantic hash input, and cost model hooks.

## Required design

Use type-indexed or validated enums for predicates, scalar expressions, sets, entities, constructors, effects, rules, schedules, and renderers. Track integer ranges, maximum collection sizes, free variables, role requirements, and fuel. Canonicalize variable names by binder order, sort commutative operands, normalize associative forms, and preserve proof annotations outside semantic hashes. Refuse unbounded recursion; permit bounded fixpoints only with explicit bound expressions.

## Public API obligations

`Type`, `TypedExpr`, `PredicateExpr`, `Definition`, `RewriteRule`, `Theory`, `TypeChecker`, `BoundChecker`, `Canonicalizer`, and `CostModel` traits.

## Test plan

Property-based well-typed AST generation; reject ill-typed substitutions; alpha-equivalence hash equality; range arithmetic soundness checked by exhaustive small domains; canonical idempotence; malformed recursion and bound overflow; serialization golden tests.

## Acceptance criteria

100,000 random well-typed terms canonicalize and typecheck deterministically; all generated values fall inside inferred bounds; alpha-equivalent theories hash identically; checker errors carry precise source path and expected/actual types.

## Forbidden shortcuts

Do not add high-level task-family operations as primitive AST tags. Convenience functions must lower to existing kernel constructs or verified intrinsics.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
