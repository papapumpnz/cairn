# WP05 — Reference and optimized RKL execution

## Objective

Execute any valid bounded theory exactly, safely, and fast enough for millions of candidate evaluations.

## Dependencies

WP03, WP04

## Owned scope

`cairn-bytecode` plus reference interpreter module in `cairn-rkl`

## Inputs

Checked RKL theories and generic REG snapshots. Frontends may provide optional typed intrinsic implementations through a versioned boundary.

## Deliverables

Slow reference interpreter, typed bytecode compiler, optimized executor, execution traces, fuel accounting, and semantic equivalence tests.

## Required design

Implement the reference interpreter directly from AST semantics. Compile validated expressions into typed micro-ops with preallocated registers, packed set columns, and specialized generic relation-query calls. Lower rules to binder loops, packed guard evaluation, effect buffers, schedule control, and modality-neutral emitted values. Record provenance at configurable trace levels. Detect conflicting writes, bound violations, and fuel exhaustion explicitly. Spatial acceleration is an optional intrinsic supplied outside the semantic core and must be equivalent to ordinary RKL/REG behavior.

## Public API obligations

`ReferenceExecutor`, `BytecodeCompiler`, `BytecodeProgram`, `FastExecutor`, `ExecutionTrace`, `ExecLimits`, and trace-level configuration.

## Test plan

Differential fuzzing between reference and optimized paths on at least one million small random theories; schedule semantics; renderer conflicts; bounded fixpoints; nested binders; empty sets; integer extremes; invalid bytecode rejection; deterministic traces.

## Acceptance criteria

Zero differential mismatches across generated scalar, relation, finite-field, rule, and transition theories; optimized simple theory execution is below 50 microseconds on the frozen 900-element-field case and equivalent non-spatial cases; compiled candidates are reused without hot-loop allocation; trace-off overhead is below 10% over the appropriate reference operation; all errors are stable and typed.

## Forbidden shortcuts

Do not let optimized semantics diverge for speed. Do not JIT native code in this package. Do not omit provenance needed by the verifier.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
