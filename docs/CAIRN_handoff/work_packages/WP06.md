# WP06 — Proof DAGs, replay certificates, and independent verifier

## Objective

Create the trust boundary that independently establishes exact execution and artifact lineage.

## Dependencies

WP01, WP03, WP04, WP05

## Owned scope

`cairn-proof`

## Inputs

Canonical learning-problem observations, checked theories, execution traces, derivation DAGs, and optional adapter verification hooks.

## Deliverables

Proof data model, demonstration replay certificates, prediction/transition/plan certificates, cross-implementation checker, corruption diagnostics, and compact proof hashes.

## Required design

Re-implement critical rule/effect/renderer semantics in a deliberately simple checker path. Verify types, bounds, definitions, derivation references, observation hashes, every demonstration outcome, request bindings, and predicted observations, transitions, goals, or plans. Validate emitted-value provenance: each effect must originate from current observations, a bounded constructor, a source-linked claim, or an explicit constant in the theory. Adapter hooks additionally verify lossless lowering and output encoding. Certificates contain enough data to replay without the synthesizer or memory store.

## Public API obligations

`IndependentVerifier`, `DemonstrationReplayCertificate`, `PredictionCertificate`, `TransitionCertificate`, `PlanCertificate`, `VerificationReport`, and command-line `cairn-verify`.

## Test plan

Bit-flip every certificate section; wrong problem/observation hash; altered theory; invalid parent; missing emitted value; duplicate emission under forbidden policy; fast-executor injected defect; adapter-lowering mismatch; semantics-version mismatch; huge proof denial-of-service bounds.

## Acceptance criteria

Verifier catches all planted corruptions; verifier agrees with the reference interpreter on one million random cases spanning three domain schemas; replay uses no synthesis, memory, spatial, or adapter crate in core semantics; typical small-problem certificate is below 1 MB; verification median is below 20 ms.

## Forbidden shortcuts

Do not import `cairn-cegis`, `cairn-memory`, or swarm proposal code. Do not trust producer scores or signatures as correctness evidence.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
