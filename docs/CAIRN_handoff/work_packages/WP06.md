# WP06 — Proof DAGs, replay certificates, and independent verifier

## Objective

Create the trust boundary that independently establishes exact execution and artifact lineage.

## Dependencies

WP01, WP02, WP03, WP04, WP05

## Owned scope

`cairn-proof`

## Inputs

Canonical task bytes, theories, execution traces, derivation DAGs.

## Deliverables

Proof data model, training replay certificates, answer certificates, cross-implementation checker, corruption diagnostics, and compact proof hashes.

## Required design

Re-implement critical rule/effect/renderer semantics in a deliberately simple checker path. Verify types, bounds, definitions, derivation references, input hashes, every training output, test binding application, and predicted grids. Validate output-cell provenance: each write must originate from observed input, bounded constructor, or explicit constant in the theory. Certificates contain enough data to replay without the synthesizer or memory store.

## Public API obligations

`IndependentVerifier`, `TrainingReplayCertificate`, `PairReplayCertificate`, `StaticAnswerCertificate`, `VerificationReport`, and command-line `cairn-verify`.

## Test plan

Bit-flip every certificate section; wrong task hash; altered theory; invalid parent; missing output write; duplicate write under forbidden policy; fast-executor injected defect; semantics-version mismatch; huge proof denial-of-service bounds.

## Acceptance criteria

Verifier catches all planted corruptions; verifier agrees with reference interpreter on one million random cases; certificate replay uses no synthesis or memory crates; typical static certificate below 1 MB; verification median below 20 ms per task.

## Forbidden shortcuts

Do not import `cairn-cegis`, `cairn-memory`, or swarm proposal code. Do not trust producer scores or signatures as correctness evidence.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
