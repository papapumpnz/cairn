# WP07 — Demand-driven entity algebra

## Objective

Generate and cache only relation-defined entity hypotheses relevant to an active explanation hole across modalities.

## Dependencies

WP03, WP04

## Owned scope

`cairn-entity`

## Inputs

Generic observations, REG facts, typed entity-expression requests, and optional frontend relation providers.

## Deliverables

Generic entity-expression evaluator, denotation cache, demand API, extension traits for frontend relations, cost tiers, equivalence signatures, and provenance.

## Required design

Implement observed-member sets, grouping by typed relations, connectivity under a supplied adjacency relation, components, ordered runs, boundaries, containers, repeated groups, equivalence classes, difference evidence, and derived calls. Spatial frontends may contribute contour, box, panel, or symmetry relations through the same evidence boundary; they are not native entity operators. A `DemandContext` includes required type, observation role, mismatch evidence, desired relations, and maximum cost. Enumerate expressions in cost order, evaluate in batches, deduplicate by denotation and scoped structural signature, and publish entity hypotheses to REG with derivations.

## Public API obligations

`EntityDemand`, `EntityGenerator`, `EntityExpr`, `EntityCatalog`, `EntitySignature`, and `DemandResult` with cap reasons.

## Test plan

Reference denotations across grid, gridworld, and vector-scene evidence; nested relation groups; ambiguous adjacency; duplicate expression merging; demand filters; deterministic cost order; cap behavior; no semantic labels inferred from frontend categorical values.

## Acceptance criteria

Useful entity hypotheses are recovered on frozen grid, gridworld, and vector-scene suites; demand-driven mode materializes at least 60% fewer entities than each frozen broad parse baseline; core API requires no spatial or ARC type; exact provenance exists for every entity.

## Forbidden shortcuts

Do not enumerate the full Cartesian product of frontend parse settings. Do not import `cairn-spatial` or adapter types. Do not assign roles such as marker or payload here.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
