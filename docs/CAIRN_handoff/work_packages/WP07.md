# WP07 — Demand-driven entity algebra

## Objective

Generate and cache only entity definitions relevant to an active explanation hole.

## Dependencies

WP02, WP03, WP04

## Owned scope

`cairn-entity`

## Inputs

Raw grids, REG facts, typed entity-expression requests.

## Deliverables

Entity expression evaluator, denotation cache, demand API, cost tiers, equivalence signatures, and provenance.

## Required design

Implement cells-where, connected sets, color-normalized and multicolor components, runs, contours, holes, boxes, panels, repeat groups, motif classes, symmetry orbits, difference regions, and derived calls. A `DemandContext` includes required type, source/target side, mismatch region, desired relations, and maximum cost. Enumerate expressions in cost order, evaluate in batches, deduplicate by denotation and scoped structural signature, and publish entities to REG with derivations.

## Public API obligations

`EntityDemand`, `EntityGenerator`, `EntityExpr`, `EntityCatalog`, `EntitySignature`, and `DemandResult` with cap reasons.

## Test plan

Reference denotations; deceptive background grids; nested components; multicolor object fixtures; duplicate expression merging; demand filters; deterministic cost order; cap behavior; no semantic labels inferred from color alone.

## Acceptance criteria

At least one useful entity definition for 99.5% of nonempty ARC training grids; demand-driven mode materializes at least 60% fewer entities than a frozen all-config parse lattice on the comparison suite; median below 20 ms per grid; exact provenance for every entity.

## Forbidden shortcuts

Do not enumerate the full Cartesian product of segmentation settings. Do not assign roles such as marker or payload here.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
