# WP08 — Spatial structure evidence frontend

## Objective

Translate finite spatial fields into cheap provenance-backed structural evidence without adding detector semantics to cognition crates.

## Dependencies

WP02, WP03, WP07

## Owned scope

`frontends/spatial-evidence`

## Inputs

Generic finite spatial fields and entity catalogs exposed through frontend contracts.

## Deliverables

Evidence facts with confidence, derivations, detector benchmarks, and manual-audit fixtures.

## Required design

Detect separator axes and frames, periodic translations, D4 symmetry support, repeated motifs under categorical renaming, lattice/checker structure, contours and holes, lines and rectangles, value-frequency/spatial distributions, small isolated token candidates, and local coordinate frames. Lower every result to generic entities, relations, events, attributes, source references, and derivations. Detectors emit evidence, not final semantics. Competing hypotheses coexist, and cognition remains unchanged if this frontend is absent.

## Public API obligations

`Detector` trait, `EvidenceBatch`, detector registry, feature flags, and per-detector metrics.

## Test plan

Positive and adversarial negative suites; noisy near-symmetry; accidental separator values; nested panels; repeated but semantically unrelated motifs; calibration of exact versus heuristic evidence.

## Acceptance criteria

Zero false exact facts on the committed detector suite; heuristic precision and recall are reported separately; median is below 30 ms per moderate field; each result has a reproducible derivation and supporting index set; no detector type crosses the frontend boundary.

## Forbidden shortcuts

Do not promote detector output directly to a control role. Do not add panel, separator, color, or grid concepts to cognition crates. Do not use outcome observations in context-only detection except explicitly transition-relative evidence.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
