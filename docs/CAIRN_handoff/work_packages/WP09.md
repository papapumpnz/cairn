# WP09 — Generic event and source-target correspondence hypothesis generation

## Objective

Generate a compact structurally diverse set of causal event hypotheses from generic before/after or observation/action/outcome evidence.

## Dependencies

WP03, WP07

## Owned scope

`cairn-events`

## Inputs

Context and outcome entity catalogs, relation evidence, change evidence, and optional action observations.

## Deliverables

Preserve, update, move, transform, rebind, copy, create, delete, split, merge, aggregate, distribute, and control event hypotheses with frontend-supplied feature indexes.

## Required design

Index entities by typed intrinsic attributes, relation neighborhoods, topology, extents where present, categorical-renaming invariants, transformed signatures supplied as evidence, and group signatures. Generate unary, zero-source, zero-target, and small hyperedge correspondences with parameter sketches rather than fully bound programs. Derive low-cost attribute and relation deltas; attach required relations and actions. Use mismatch evidence to demand additional entities. Preserve structural diversity by event kind and arity rather than one global score beam. Spatial indexes from WP08 are optional evidence providers, never a crate dependency.

## Public API obligations

`EventGenerator`, `EventHypothesis`, `ParameterSketch`, `EventIndex`, and per-kind generator traits.

## Test plan

Independent generators covering every event kind in grid transformations, interactive worlds, and vector scenes; distractors; one-to-many and many-to-one; categorical rebinding; context changes; local frames where provided; exact coverage accounting; deterministic ranking.

## Acceptance criteria

Correct event kind and source-target set is top-five on at least 98% of single-event generated cases across all three domains; top-twenty on at least 95% of two-event cases; median is below 20 ms per simple transition and p95 below 100 ms; spatial evidence is optional; cap reasons are reported.

## Forbidden shortcuts

Do not require one input object to map to one output object. Do not discard zero-source creation or variable-arity groups.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
