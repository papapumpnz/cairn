# WP09 — Event and source-target correspondence hypothesis generation

## Objective

Generate a compact topologically diverse set of causal event hypotheses from an input-output pair.

## Dependencies

WP02, WP03, WP07, WP08

## Owned scope

`cairn-events`

## Inputs

Input and output entity catalogs, structural evidence, changed-cell masks.

## Deliverables

Preserve, update, move, transform, recolor, copy, create, delete, split, merge, aggregate, distribute, panel, and symbol-control event hypotheses.

## Required design

Index entities by exact shape, color-normalized shape, topology, dimensions, palette multiset, transformed signature, and group signature. Generate unary, zero-source, zero-target, and small hyperedge correspondences with parameter sketches rather than fully bound programs. Derive low-cost coordinate and color deltas; attach required relations. Use changed regions to demand additional entities. Preserve structural diversity by event kind and arity rather than one global score beam.

## Public API obligations

`EventGenerator`, `EventHypothesis`, `ParameterSketch`, `EventIndex`, and per-kind generator traits.

## Test plan

Independent synthetic generator covering every event kind; distractors; one-to-many and many-to-one; multicolor construction; changed background; panel-local coordinates; exact coverage accounting; deterministic ranking.

## Acceptance criteria

Correct event kind and source-target set in top five on at least 98% of single-event synthetic cases; top twenty on at least 95% of two-event component cases; median below 20 ms per simple pair and p95 below 100 ms; emitted event count cap reasons reported.

## Forbidden shortcuts

Do not require one input object to map to one output object. Do not discard zero-source creation or variable-arity groups.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
