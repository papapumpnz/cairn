# WP10 — Exact demonstration event-cover optimization

## Objective

Select top structurally distinct event sets that exactly explain a generic demonstration transition.

## Dependencies

WP09, WP13 when available; provide temporary exact-cover backend initially

## Owned scope

`cairn-cover`

## Inputs

Event hypotheses, evidence coverage, effect constraints, and observation-builder candidates.

## Deliverables

Demonstration event covers, replay plans, unmatched evidence cores, cover diversity signatures, and optimization metrics.

## Required design

Form weighted exact-cover or finite-domain constraints over event selection, outcome-evidence production, context-change accounting, source-use policy, effect conflicts, and parameter compatibility. Solve lexicographically for exactness, event cost, literals, entity cost, and reuse. Enumerate top covers with semantic blocking clauses. If exact cover is impossible, compute a minimized or labeled non-minimal core identifying unmatched outcome evidence, missing source, constructor, arity, effect, or relation. Adapter-specific coverage maps are optional lowered evidence.

## Public API obligations

`CoverProblem`, `CoverSolver`, `DemonstrationEventCover`, `CoverReplayPlan`, `ExplanationCore`, and `CoverEnumerator`.

## Test plan

Brute-force comparison on small event sets in three schemas; conflicting effects; duplicate semantic events; impossible coverage; one unexplained entity/relation; cap versus unsat distinction; deterministic top-k; replay equality.

## Acceptance criteria

An exact cover is top-eight for at least 95% of two-event generated transitions across grid, gridworld, and vector schemas; replay correctness is 100%; p95 is below 200 ms; top-k covers are structurally distinct; omission cores classify at least 90%.

## Forbidden shortcuts

Do not treat a literal output copy as an admissible low-cost event. Do not call a capacity cap unsatisfiable.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
