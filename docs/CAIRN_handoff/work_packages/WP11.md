# WP11 — Cross-demonstration analogical alignment and anti-unification

## Objective

Map causal roles and relations across demonstrations and produce typed rule sketches.

## Dependencies

WP03, WP10

## Owned scope

`cairn-analogy`

## Inputs

Top demonstration event covers, REG neighborhoods, entity and event signatures.

## Deliverables

Role mappings, event clusters, preserved-relation scores, alignment modes, and anti-unified sketches.

## Required design

Construct event graphs whose nodes are event participants and context entities. Generate candidate local-role matches by causal kind and relation signature. Use beam or exact small-graph matching to maximize systematic relational preservation under consistency constraints. Canonicalize abstract role names. Anti-unify aligned event parameters, preserving competing literal and grounded-variable hypotheses. Reject generalized variables that cannot be bound from observations.

## Public API obligations

`AlignmentProblem`, `Alignment`, `RoleMap`, `EventCluster`, `AntiUnifier`, `RuleSketch`, and structural signature functions.

## Test plan

Generated demonstrations across three domains with permuted categorical values, positions where present, sizes, counts, distractors, swapped roles, and deceptive appearance matches; exact mapping up to renaming; ambiguous-mode retention; grounding rejection.

## Acceptance criteria

Correct abstract role alignment in top three for at least 95% of synthetic suite; at least 90% on multirule suite; relation preservation beats appearance-only baseline by at least 15 points; median below 100 ms for small tasks and p95 below 1 s.

## Forbidden shortcuts

Do not force one global mapping when multiple modes remain. Do not generalize a constant merely because it differs syntactically; require a typed grounding path.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
