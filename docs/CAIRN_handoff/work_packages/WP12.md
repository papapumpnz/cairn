# WP12 — Typed e-graph and goal-directed equality saturation

## Objective

Compact equivalent predicates, features, coordinate expressions, and constructors while preserving proof scope.

## Dependencies

WP04, WP05

## Owned scope

`cairn-egraph`

## Inputs

Typed RKL expressions, algebraic rewrites, task-local value vectors.

## Deliverables

Typed e-classes, e-class analyses, scoped observational equivalence, goal-directed saturation, and k-best extraction.

## Required design

Implement or wrap an e-graph with explicit type partitioning. Add rebuilding, hash-consing, proof-carrying unions, and analyses for cost, free variables, bounds, value vectors, grounding, symmetry behavior, and compiler availability. Universal rewrites require checked algebraic rules. Observational equality is task-scoped and tagged. Saturate only neighborhoods relevant to active holes and stop on node, time, or novelty caps.

## Public API obligations

`TypedEGraph`, `EClassId`, `EqualityProof`, `EClassAnalysis`, `RewriteSet`, `ExtractionCost`, and serialization of compact task-local fragments.

## Test plan

Known equality laws; type-conflicting union rejection; unsound observational export rejection; extraction optimality on enumerable small classes; node-cap determinism; proof replay; rewrite loops.

## Acceptance criteria

At least 10 times syntactic deduplication on generated equivalent-expression suites; k-best extraction exact against brute force for small classes; 100,000-node stress within declared memory; goal-directed run below 100 ms for typical guard holes; no cross-task observational equality leakage.

## Forbidden shortcuts

Do not declare value-vector equality a universal theorem. Do not run unconstrained global saturation.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
