# WP13 — Incremental finite-domain SAT and MaxSAT backend

## Objective

Provide deterministic incremental solving, model blocking, optimization, and unsat explanation behind a stable trait.

## Dependencies

WP00, WP01, WP04

## Owned scope

`cairn-constraints`

## Inputs

Finite-domain variables and semantic constraints from cover and theory components.

## Deliverables

Backend abstraction, first production SAT backend, weighted or lexicographic optimization, assumption scopes, metrics, and core extraction.

## Required design

Encode bounded enums with one-hot or binary representations chosen by domain size; support cardinality, implication, equality, ordering, reachability templates, and soft costs. Use an open-source CPU SAT solver through a narrow audited FFI or a pure-Rust backend if performance is adequate. Implement lexicographic optimization through iterative bounds or native MaxSAT. Maintain assumptions for sketch-local clauses and semantic model blocking.

## Public API obligations

`ConstraintBackend`, `ProblemHandle`, variable builders, hard and soft constraints, `SolveResult`, `Model`, `UnsatCore`, and solver metrics.

## Test plan

Truth-table tests for each encoding; random small problem comparison to brute force; incremental add and retract by assumptions; model blocking; optimization tie breaks; timeout and cap behavior; malformed FFI response defense.

## Acceptance criteria

All brute-force comparisons pass; solve 100,000-variable sparse synthetic problem within measured target chosen in pre-registration; incremental re-solve at least 5 times faster than rebuild on CEGIS fixture; deterministic selected model under CAIRN canonical tie-breaking.

## Forbidden shortcuts

Do not expose backend-specific model order as semantic ranking. Do not let an FFI solver bypass resource accounting.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
