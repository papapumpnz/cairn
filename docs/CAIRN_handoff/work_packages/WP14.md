# WP14 — Contextual guard and selector induction

## Objective

Learn minimal relational clauses that select transformed bindings and reject hard negatives.

## Dependencies

WP11, WP12, WP13

## Owned scope

`cairn-guards`

## Inputs

Positive and negative bindings from aligned event clusters, REG facts, predicate e-classes.

## Deliverables

Guard hypotheses, decision lists when required, separation reports, and failure constraints.

## Required design

Materialize predicate candidate value vectors in cost tiers. Search conjunctions first using bitset coverage and learning-from-failures constraints. A too-general clause blocks its generalizations; a too-specific clause blocks specializations that lose required positives. Add bounded disjunction or decision list only when conjunction unrealizable. Include relation paths, ranks, uniqueness, group aggregates, panel context, and symbol relations. Penalize ungrounded literals.

## Public API obligations

`GuardProblem`, `GuardInducer`, `GuardHypothesis`, `BindingTable`, `SeparationReport`, and `GuardFailure`.

## Test plan

Relational-role suite with identical appearance, XOR-like cases requiring decision list, empty selector, unique rank, multiple valid clauses, hard negatives, cross-pair literal traps, deterministic minimality.

## Acceptance criteria

At least 95% held-out selector accuracy on T0 suite; exact demonstration positives and negatives; full system at least 3 times fewer guard candidates than naive enumeration; emitted guard has replayable binding explanation.

## Forbidden shortcuts

Do not accept selectors defined by source pair index. Do not silently use output facts when a test-time selector must bind from input only.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
