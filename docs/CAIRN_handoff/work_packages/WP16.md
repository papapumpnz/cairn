# WP16 — Operator-valued symbol interpretation

## Objective

Infer when visual tokens act as instructions and bind them to values, predicates, operators, constructors, roles, or schedule choices.

## Dependencies

WP11, WP14, WP15

## Owned scope

`cairn-symbols`

## Inputs

Candidate symbol entities, event variation across demonstrations, legends, role alignments, guard and constructor families.

## Deliverables

Symbol-control hypotheses, mapping constraints, operator-valued bindings, and negative-control diagnostics.

## Required design

Detect causal covariance between token signatures and event/theory choices. Build candidate meanings from effects already required by each demonstration rather than enumerate operators globally. Solve maps under bijection, many-to-one, compositional, orientation-derived, categorical-derived, or legend-pairing structures. Account for symbol consumption versus emission. Require the symbol to be available in prediction context and its mapping to predict held-out demonstrations.

## Public API obligations

`SymbolProblem`, `SymbolSignature`, `SymbolMeaning`, `SymbolMapTheory`, `SymbolInterpreter`, and symbol evidence report.

## Test plan

Tokens with permuted appearance, directional tokens, categorical keys, legends, irrelevant motifs, multiple tokens, operator-valued transform and selector meanings, collisions, and unseen symbols with compositional semantics across spatial and non-spatial schemas.

## Acceptance criteria

At least 90% held-out exact task solve on T3 suite; at least 80% operator-valued cases; unrelated-symbol false control below 2%; leave-one-out mapping report; runtime below 2 s median on suite.

## Forbidden shortcuts

Do not hardcode glyphs or categorical meanings. Do not treat every small entity as an instruction.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
