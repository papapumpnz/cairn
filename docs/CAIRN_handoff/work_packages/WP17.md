# WP17 — Rule schedule, dependency DAG, canvas, and renderer synthesis

## Objective

Infer how multiple rules interact and how their effects become the exact output canvas.

## Dependencies

WP10, WP13, WP15

## Owned scope

`cairn-schedule`

## Inputs

Rule sketches, event covers, effect read/write sets, constructor outputs, dimension evidence.

## Deliverables

Parallel/sequence/decision/fixpoint schedules, dependency DAGs, canvas expressions, layer order, and conflict proofs.

## Required design

Compute potential dependencies from created/read entities and relations, changed/read evidence, observation construction, and conflicting effects. Solve the minimal orientation satisfying all demonstration replays. Infer parallel execution where no dependency exists. Detect repeated same-form events and propose bounded fixpoints with progress measures. Synthesize outcome bounds from context evidence, containers, extents where present, counts, and repetition. Resolve conflicts only through explicit order or inferred priority predicates.

## Public API obligations

`ScheduleProblem`, `DependencyDag`, `ScheduleSynthesizer`, `CanvasExpr`, `RendererSynthesizer`, and conflict reports.

## Test plan

Independent rules, order-sensitive rules, conflicting writes, conditional branch, monotone fixpoint, nonterminating candidate rejection, crop/recolor, expansion, panel rendering, dimension derivation.

## Acceptance criteria

At least 90% semantic schedule recovery on T2; at least 85% exact interacting-rule solves; 100% bound proofs for fixpoints; renderer reproduces all selected event covers; p95 below 2 s on synthetic suite.

## Forbidden shortcuts

Do not default to arbitrary source order. Do not hide conflicts under last-write-wins unless that policy is explicitly inferred and verified.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
