# WP18 — Theory weaver and semantic frontier

## Objective

Assemble aligned events, guards, constructors, symbols, schedules, and renderers into complete multi-rule theory candidates.

## Dependencies

WP11, WP14, WP15, WP16, WP17

## Owned scope

`cairn-theory`

## Inputs

Alignment modes and component hypothesis streams.

## Deliverables

Theory sketches, joint constraint problems, complete candidates, semantic mode hashes, and anytime frontier state.

## Required design

Iterative-deepen by theory shape cost rather than raw AST size. Candidate shapes include one quantified rule, rule plus renderer, multiple independent rules, dependency DAG, decision list, symbol-controlled branch, and bounded fixpoint. Jointly constrain shared roles and parameters across components. Use component lower bounds to prune. Enumerate semantically distinct theories via canonical hashes and output modes. Preserve partial theories with explicit unresolved holes for ontology invention.

## Public API obligations

`TheoryWeaver`, `TheorySketch`, `TheoryCandidate`, `TheoryFrontier`, `CandidateOrigin`, and checkpoint serialization.

## Test plan

Component mock composition; shared-variable conflicts; multiple alignments; semantic deduplication; anytime stop and resume; deterministic frontier order; complete synthetic theory reconstruction.

## Acceptance criteria

On T0–T3 combined suite, complete correct theory in top fifty executed candidates for at least 90% of solved cases; no duplicate semantic theory execution above 1%; checkpoint/resume byte-identical results; memory caps produce typed terminal state.

## Forbidden shortcuts

Do not flatten all tasks to one rule. Do not let learned scheduler weights remove a theory shape from reachability.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
