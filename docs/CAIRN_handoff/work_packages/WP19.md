# WP19 — Counterexample-guided refinement and learning from failures

## Objective

Turn exact execution failures into semantic pruning constraints and focused follow-up jobs.

## Dependencies

WP06, WP18

## Owned scope

`cairn-cegis`

## Inputs

Theory candidates, execution traces, demonstration outputs, constraint scopes.

## Deliverables

Structured counterexamples, minimized explanation cores, pruning clauses, refinement jobs, and unrealizability certificates.

## Required design

Compare expected and actual output by cells, entities, event coverage, bindings, rule conflicts, and renderer writes. Attribute mismatches to the smallest active theory components possible. Translate too-general/too-specific guards, invalid constructors, literal failures, schedule conflicts, symbol collisions, and missing arity into semantic blocking constraints. Ask backend for unsat cores and minimize through deletion where affordable. Trigger ontology jobs only when current sketch is proven unrealizable or repeated cores support it.

## Public API obligations

`CegisLoop`, `Counterexample`, `ExplanationCore`, `ConstraintDelta`, `RefinementPlanner`, and `UnrealizabilityCertificate`.

## Test plan

One fixture for every core kind; equivalent-syntax pruning; non-minimal core labeling; cap versus unsat; repeated failure convergence; comparison against rejection-only baseline.

## Acceptance criteria

T5 shows at least 3 times fewer complete candidate executions and 2 times lower p95 than rejection-only; no valid theory pruned on exhaustive small suites; core classification at least 90% on controlled omissions.

## Forbidden shortcuts

Do not convert every mismatch into a blanket block of one syntax tree. Do not trigger invention merely because a low-budget search failed.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
