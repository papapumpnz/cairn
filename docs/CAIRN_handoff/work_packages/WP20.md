# WP20 — Dynamic predicate, role, constructor, and recursive-definition invention

## Objective

Expand the task-local practical language from explanation cores while remaining grounded in RKL.

## Dependencies

WP12, WP13, WP19

## Owned scope

`cairn-invent`

## Inputs

Positive and negative bindings, unmatched target regions, repeated partial derivations, minimized cores.

## Deliverables

Definition proposals, totality proofs, separation/compression reports, task-local admission, and promotion candidates.

## Required design

Implement contrast-driven feature search over attributes, relation aggregates, paths, topology, symmetry, comparisons, and small compositions. For constructors, synthesize from unmatched region provenance and anti-unify partial builds. For hidden roles, require an observable binder such as a control symbol. For recursion, infer repeated step form and progress measure, then validate against unrolled reference. Rank by exact core reduction, leave-one-out prediction, grounding, and description gain.

## Public API obligations

`DefinitionInventor`, specialized `PredicateInventor`, `ConstructorInventor`, `RoleInventor`, `RecursionInventor`, `DefinitionProposal`, and `AdmissionReport`.

## Test plan

Deliberately omitted-vocabulary suites, hard negatives, ungrounded latent rejection, recursion termination, literal-grid temptation, broad versus narrow parameter variation, false-positive negative suite.

## Acceptance criteria

T4 gate: at least 70% of omitted-vocabulary cases solved, negative false positives below 2%, every accepted definition exact and total, median invention below 10 s, no task IDs or opaque native semantics.

## Forbidden shortcuts

Do not add a Rust primitive for each invented concept. Do not promote a one-task definition automatically.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
