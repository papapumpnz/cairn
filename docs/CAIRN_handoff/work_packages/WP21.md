# WP21 — Falsification, theory ranking, ambiguity management, and pass@2

## Objective

Rank exact theories by internal predictive evidence and emit two credible distinct output modes.

## Dependencies

WP18, WP19, WP20

## Owned scope

`cairn-falsify`, `cairn-belief`

## Inputs

Exact theories, certificates, task demonstrations, applicable transformations, resource budget.

## Deliverables

Leave-one-out reports, equivariance results, perturbation stability, semantic modes, belief weights, and attempt selection.

## Required design

Refit or rebind top theories on leave-one-out subsets. Re-derive under applicable D4 and safe palette renamings. Test component decomposition and bounded irrelevant-feature perturbations. Cluster theories by semantic signature and predicted test outputs. Compute structured evidence terms rather than one opaque score. Choose attempt one by lexicographic criteria; choose attempt two for posterior coverage and disagreement.

## Public API obligations

`Falsifier`, `FalsificationReport`, `TheoryScorer`, `TheoryBeliefSet`, `OutputMode`, and `AttemptSelector`.

## Test plan

Controlled ambiguity generators; fixed-semantic color where permutation is invalid; two syntax-equivalent theories; two semantic theories with same output; leave-one-out unavailable; second-attempt diversity.

## Acceptance criteria

A0 at least 8-point ambiguous-task improvement over MDL-only; A1 pass@2 at least 10 points over best single mode in controlled suite; duplicate second outputs below 1%; exact training fit never relaxed.

## Forbidden shortcuts

Do not assume every color permutation is valid. Do not present heuristic weights as calibrated probabilities without calibration evidence.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
