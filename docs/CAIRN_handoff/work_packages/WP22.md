# WP22 — ARC-AGI-1/2 frontend and static task runner

## Objective

Parse official task format, enforce split capabilities, run static tasks, and emit standard answer and evidence artifacts.

## Dependencies

WP02, WP06

## Owned scope

`cairn-arc12`

## Inputs

Dataset roots supplied at runtime, solver trait, verifier.

## Deliverables

Strict JSON parser, task canonicalization, training/public-eval capability separation, answer writer, suite runner, and task visualization for development only.

## Required design

Validate all dimensions, colors, train/test structure, and attempts. Hash canonical task bytes. Expose only task data, never path-derived semantics. Use capability tokens for training versus evaluation roots. Evaluation runner seals per-task diagnostic details until run completion. Support deterministic task ordering, resume from committed journal, and no partial result overwrite.

## Public API obligations

`ArcTaskLoader`, `DatasetCapability`, `StaticSolver` trait, `SuiteRunner`, answer serialization, and development visualization command.

## Test plan

Malformed JSON, uneven rows, invalid colors, missing train/test, path traversal, evaluation capability misuse, deterministic ordering, interrupted-run resume, answer formatting against fixtures.

## Acceptance criteria

All official public task files parse; malformed corpus fixtures rejected precisely; ordinary development binary cannot enumerate evaluation roots; one-task end-to-end dummy solver certificate verifies; runner overhead below 5 ms per task excluding solve.

## Forbidden shortcuts

Do not expose task filename to the solver. Do not import evaluation data in unit tests.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
