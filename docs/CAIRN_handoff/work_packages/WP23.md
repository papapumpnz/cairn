# WP23 — Mechanism memory, promotion, uncertainty, and deprecation

## Objective

Persist proof-backed causal definitions without repeating SCEM's surface-content transfer failure.

## Dependencies

WP01, WP06, WP20

## Owned scope

`cairn-memory`

## Inputs

Task-local definitions, certificates, held-out support, counterexamples, transfer experiments.

## Deliverables

Mechanism module store, support geometry, proposal retrieval, offline promotion runner, memory-off ablation, and deprecation workflow.

## Required design

Represent each module as RKL definition plus binder and verifier. Track which latent dimensions and contexts varied. Promotion uses task-level held-out folds, negative generators, compression and speed metrics, and current-task re-verification. Retrieval indexes typed signatures, relation patterns, and evidence fingerprints; it returns proposals only. Counterexamples update module status and may trigger quarantine or deprecation.

## Public API obligations

`MechanismStore`, `MechanismModule`, `SupportGeometry`, `PromotionCandidate`, `PromotionRunner`, `MechanismQuery`, and module audit CLI.

## Test plan

Broad/narrow synthetic regimes; unsupported dimension uncertainty; malicious literal task content; module counterexample; deprecation; memory-off exactness; retrieval determinism; store corruption.

## Acceptance criteria

A2 gates pass; zero unverified accepts; broad modules transfer at least 90% on suite; narrow modules do not claim support beyond evidence; retrieval median below 1 ms for 100,000 modules in stress index; full lineage available.

## Forbidden shortcuts

Do not store solved test outputs or full source grids as mechanism bodies. Do not let retrieval veto non-memory search.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
