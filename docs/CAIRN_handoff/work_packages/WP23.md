# WP23 — Mechanism memory, promotion, uncertainty, and deprecation

## Objective

Run consolidation separately from online solving: compress repeated proof and
execution graphs, anti-unify variations, track support geometry and real reuse,
and promote only when held-out transfer measurably reduces future learning cost.

Make experience measurably reduce future demonstrations or CPU search while correctness remains verifier-controlled.

## Dependencies

WP01, WP04, WP06

## Owned scope

`cairn-memory`

## Inputs

Typed task-local mechanisms, certificates, held-out support, counterexamples, and frozen curricula. WP20 later supplies richer ontology definitions through the same proposal API.

## Deliverables

Mechanism module store, support geometry, proposal retrieval, offline promotion runner, fixed-budget memory-off ablation, demonstration-efficiency measurement, and deprecation workflow.

## Required design

Represent each module as an RKL definition or executable schema plus binder and verifier. Track which latent dimensions and contexts varied. Promotion uses task-level held-out folds, negative generators, compression, search, and demonstration metrics. Retrieval indexes typed signatures and relation patterns; it returns proposals only. Every cohort runs the same frozen related and unrelated sets with memory enabled and disabled at equal CPU budgets. Counterexamples update status and may trigger quarantine or deprecation.

## Public API obligations

`MechanismStore`, `MechanismModule`, `SupportGeometry`, `PromotionCandidate`, `PromotionRunner`, `MechanismQuery`, and module audit CLI.

## Test plan

Broad/narrow regimes; changed values, sizes, counts, and layouts; related/unrelated frozen sets; reduced-demonstration curves; malicious literal content; counterexamples; deprecation; memory-off exactness; retrieval determinism; store corruption.

## Acceptance criteria

GLL-2 passes: memory reduces median search by at least 50% and demonstrations required, exact accuracy does not fall on related or unrelated sets, modules rebind across all tested variation dimensions, zero unverified accepts occur, and full lineage is available.

## Forbidden shortcuts

Do not store solved test outputs or full source grids as mechanism bodies. Do not let retrieval veto non-memory search.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.

## Implementation checkpoint — 2026-07-11

`cairn-consolidator` now exposes a bounded, separate offline runtime over typed
immutable proof DAGs. It automatically cohorts episodes by ancestral
operation/type/topology shape, anti-unifies typed opaque arguments, shares
parameters with identical variation, excludes unrelated branches, calculates
explicit compression cost, and exactly reconstructs all sources before
proposal emission. `cairn-memory::PromotionRunner::promote_compressed` requires
the opaque proposal lineage to match the independently invented definitions and
records compression metrics in the provisional module.

The frozen scalar G0 rerun records 12 to seven proof units, two replayed source
graphs, 10/10 held-out transfer, and 440 versus ten candidate executions. The
remaining WP23 work includes canonical CAS persistence, counterexample-driven
automatic deprecation, graph-edit anti-unification, compiled-module lifecycle,
and arbitrary internal-subgraph extraction.

The follow-on compiler converts the accepted whole-definition cohort into a
fresh `invented_mechanism_*` RKL definition with alpha-normalized parameters and
generalized observed type bounds. The definition is type/totality checked and
structurally replayed against every source. `cairn-verifier` independently
reimplements ancestral extraction, pattern instantiation, and cost calculation;
its opaque token is mandatory for compressed promotion. Canonical graph
persistence, graph-edit anti-unification, arbitrary internal-subgraph helper
extraction, compiled-module lifecycle, and counterexample-driven automatic
deprecation remain open.

## Persistence checkpoint — 2026-07-12

Reuse evidence now has a separate canonical CAS path under memory semantics
1.5.0. Verifier-issued receipts persist with theory identity, experience scope,
lineage, verified-case count, and frozen counterfactual metrics. After process
restart, loading is untrusted; the verifier replays the referenced checked
theory and experience before the consolidator may issue promotion. Tests cover
idempotency, CAS recovery, restart promotion, malformed payloads, missing
lineage, changed theory, and changed expected behavior.

Canonical proof graphs now persist under consolidator semantics 2.1.0 and
schema `cairn.consolidator.proof-graph` version 1. A restart test reloads three
typed DAGs, re-admits them, reproduces the identical compression proposal hash,
and passes independent source/cost replay. Missing lineage, cyclic topology,
and malformed payloads fail closed.

Under consolidator semantics 2.2.0, bounded exhaustive contiguous-window mining
now extracts a connected internal helper across differently shaped host proofs.
External inputs become typed boundary parameters, typed values are anti-unified,
all sources are reconstructed exactly, and `InternalCompressionVerifier`
separately checks topology, bindings, replay, cost, and identity. Four source
hosts compress from 28 to 20 proof units and one changed held-out host rebinds
exactly. See ADR-0011 and the internal-subgraph experiment evidence.

Under consolidator semantics 2.3.0, evidence-bearing internal proposals compile
into canonical source-independent executable proof schemas. Two disjoint
four-episode cohorts converge on the same mechanism identity. The independent
verifier derives fixed-work reuse metrics, and memory semantics 1.6.0
automatically requests a separate consolidator certificate after the second
qualifying runtime receipt. Candidate windows fall from 18 to nine/five,
examples from four to one, and proof units from 28 to four.

Arbitrary non-contiguous graph-edit anti-unification, RKL lowering for operations
with explicit reference semantics, durable compiled-module storage,
counterexample-driven automatic deprecation, and broad curricula remain open.
