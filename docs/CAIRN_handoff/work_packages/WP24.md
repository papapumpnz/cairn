# WP24 — Local multi-process cognitive swarm

## Objective

Run heterogeneous agents concurrently on one CPU machine with deterministic artifact merging and exact accounting.

## Dependencies

WP01, WP06, WP18

## Owned scope

`cairn-swarm` local runtime

## Inputs

Job and artifact protocols, role workers, CAS.

## Deliverables

Coordinator, resource broker, worker runtime, leases, journals, local transport, crash recovery, and scaling benchmark.

## Required design

Use one coordinator and isolated worker processes connected by Unix sockets or loopback. Persist job state in append-only journal. Workers advertise capabilities, lease bounded jobs, publish partial immutable artifacts, and heartbeat. Broker scores expected core reduction or solve value per CPU. Deterministic mode uses fixed queue and canonical merge. Pin or group workers by physical core to reduce oversubscription.

## Public API obligations

`Coordinator`, `WorkerRuntime`, `ResourceBroker`, `Job`, `JobResult`, `Lease`, `CapabilitySet`, and local swarm CLI.

## Test plan

Worker crash, coordinator restart, duplicate result, late result, artifact corruption, lease expiry, deterministic result across 1/2/4/8 workers, CPU accounting, bounded queue backpressure.

## Acceptance criteria

S0 speed gates; semantic results identical across worker counts; zero lost accepted artifacts after crash recovery; coordinator overhead below 5% on four-worker search-heavy suite; each role CPU reported.

## Forbidden shortcuts

Do not share mutable theory objects between processes. Do not count thread oversubscription as speedup.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
