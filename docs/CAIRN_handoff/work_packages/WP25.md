# WP25 — Distributed swarm transport and integrity

## Objective

Extend the artifact/job protocol across CPU nodes without trusting remote producers.

## Dependencies

WP24

## Owned scope

network transport module in `cairn-swarm`

## Inputs

Local swarm protocol, CAS, worker capabilities.

## Deliverables

Versioned framed transport, authenticated optional identities, resumable blob fetch, backpressure, node-loss recovery, and corruption tests.

## Required design

Implement QUIC or TCP framing with protocol negotiation, maximum sizes, hash-before-commit, and explicit semantics versions. Send envelopes first and fetch large blobs on demand. Reconstruct value vectors locally where cost model says cheaper. Remote verification claims remain untrusted until local or independent replay. Support task-level sharding first and within-task sharding only for hard jobs.

## Public API obligations

`RemoteWorker`, `Transport`, `BlobTransfer`, `ProtocolNegotiation`, node registry, and distributed-run manifest.

## Test plan

Network partition, node loss, duplicate connection, version mismatch, malformed frame, oversized blob, hash corruption, replay under wrong task, slow consumer, resume after interruption.

## Acceptance criteria

S2 gates; four-node task-sharded overhead below 15%; corrupted artifacts rejected; no semantic difference from local run; node loss completes remaining tasks; transport can be disabled without core changes.

## Forbidden shortcuts

Do not transmit or load native code. Do not trust a signed remote answer without replay.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
