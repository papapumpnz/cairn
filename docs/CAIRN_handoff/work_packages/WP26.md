# WP26 — Generic temporal evidence, entity tracking, and interactive adapter SDK

## Objective

Normalize generic observation-action-outcome histories into compressed temporal evidence without depending on ARC adapters.

## Dependencies

WP03, WP07, WP29

## Owned scope

`cairn-temporal`, `adapters/interactive`

## Inputs

Generic observations, action schemas, outcome observations, and optional progress evidence. ARC-AGI-3 is a separately versioned adapter client.

## Deliverables

Temporal observations, candidate tracks, change events, action records, viewport/camera hypotheses, history summaries, replayable episode store, and interactive adapter conformance tests.

## Required design

Track entities through exact overlap, transformed shape, motion, and appearance signatures while retaining alternatives. Distinguish object motion from camera motion via global consensus. Emit action-labeled event transitions and landmark states. Store raw frames once in CAS; maintain compressed event summaries and links. Do not assign game-specific semantic names.

## Public API obligations

`InteractiveFrontend`, `TemporalEvidenceBuilder`, `TransitionEvidence`, `TrackHypothesis`, `HistorySummary`, `EpisodeStore`, and generic action-space description.

## Test plan

Synthetic moving objects, camera pan, appearing/disappearing items, occlusion, toggles, counters, resets, ambiguous tracks, long episodes with bounded working memory, API error handling.

## Acceptance criteria

Correct event/track in top three for at least 95% controlled suite; working-memory size grows sublinearly and remains below configured cap for 10,000 steps; raw episode replay exact; common update below 100 ms.

## Forbidden shortcuts

Do not branch on environment or level ID. Do not keep all raw observations in active planner state. Do not place ARC-AGI-3 concepts in `cairn-temporal`.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
