# WP27 — World-theory induction, hidden state, goal hypotheses, and intervention design

## Objective

Maintain competing executable world and goal theories, select discriminating
interventions by information gain/progress/risk, and invent testable latent
state when visible-state theories all fail.

Learn previously unseen action-conditioned dynamics and choose informative, goal-relevant experiments from generic temporal evidence.

## Dependencies

WP05, WP13, WP26

## Owned scope

world-model modules in `cairn-theory` and `cairn-plan`

## Inputs

Temporal events, action history, candidate RKL transition rules, progress observations.

## Deliverables

World theories, latent state schemas, executable goal hypotheses, belief updates, expected-information intervention proposals.

## Required design

Align action-event transitions across time and anti-unify into rules. Introduce hidden state only when similar visible states have different outcomes or persistent causes are required. Infer goal predicates from rewards, resets, irreversible progress, and recurrent target-state structure. For interventions, simulate top theory modes, cluster predicted observations, weight partitions by belief mass, calculate expected entropy reduction plus goal value, action cost, and irreversible risk.

## Public API obligations

`WorldTheoryLearner`, `WorldTheory`, `LatentSchema`, `GoalHypothesis`, `InterventionPolicy`, `ActionCandidate`, and belief update API.

## Test plan

Hidden switches, keys, obstacles, stochastic-looking but deterministic latent dynamics, deceptive reward, irreversible traps, information-gain tie cases, random-probe baseline.

## Acceptance criteria

GLL-4, I0, and I1 pass; active policy uses at least 30% fewer actions than random; transition prediction is at least 95%; an executable goal is top-three at least 90%; action efficiency improves over episodes; a learned option transfers to changed layouts; no arbitrary per-step latent labels.

## Forbidden shortcuts

Do not compute information gain as count of distinct outcomes alone. Do not assume the first positive reward fully defines the goal.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
