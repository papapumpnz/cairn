# WP28 — Belief-aware planning and option induction

## Objective

Induce conditional, parameterized skills from causal trace segments and require
unseen composition through explicit preconditions/effects; recorded action
sequences do not count as skills.

Plan through learned theories, compose independently learned mechanisms, and compress repeated successful behavior into verified options.

## Dependencies

WP05, WP27

## Owned scope

`cairn-plan`

## Inputs

Belief state, world theories, goals, action space, episode history.

## Deliverables

Deterministic A*, contingent AO*, bounded MCTS, plan certificates, option theories, and planner selection policy.

## Required design

Use symbolic state hashes and admissible domain-independent heuristics where available. When theory posterior is concentrated, use deterministic planning. When observations can resolve theories, build a bounded belief tree. Use MCTS only for large or stochastic spaces, with exact model rollout where possible. Mine repeated action-event segments into initiation, policy, termination, expected-effect, and failure clauses; verify on distinct contexts. Include a held-out curriculum in which two mechanisms are learned independently and later combined through ordinary binders, schedules, and planner machinery without a new composite operator.

## Public API obligations

`Planner` trait, `AStarPlanner`, `AOPlanner`, `MctsPlanner`, `PlanResult`, `OptionTheory`, `OptionInducer`, and planner metrics.

## Test plan

Shortest path, contingent door/key, hidden dynamics requiring experiment, sparse reward, independently learned containment-plus-ordering composition, option false initiation, changed layout, planner timeout, deterministic tie breaks.

## Acceptance criteria

GLL-3 and I2 pass; independently learned mechanisms compose without a coded composite operator; options reduce expansions at least 5 times on held-out layouts; deterministic planner returns optimal paths on exhaustive small worlds; plan replay is exact.

## Forbidden shortcuts

Do not store raw action sequences as skills. Do not use game-specific heuristic code. Do not add a composite operator to pass the composition suite.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
