# WP29 — Modality frontend SDK and vector-graphics frontend

## Objective

Define the generic observation extension boundary early and prove it on an exact non-grid visual modality.

## Dependencies

WP03, WP04

## Owned scope

`cairn-frontend-sdk`, `frontends/graphics`

## Inputs

Vector scene files or programmatic scenes.

## Deliverables

Frontend trait, generic learning-problem builder, uncertainty conventions, source-reference schema, verifier-hook contract, and graphics-to-REG adapter.

## Required design

Map paths, shapes, groups, layers, transforms, fills, strokes, constraints, and animation events to entities and relations. Preserve exact source geometry. Frontend proposals carry derivations and optional uncertainty. Define how modality-specific equality and rendering verification integrates without changing RKL semantics.

## Public API obligations

`Frontend`, `ObservationBundle`, `EvidenceEmitter`, `ModalityVerifier`, source references, and graphics adapter CLI.

## Test plan

SVG-like fixtures with groups, transforms, paths, clipping, repeated symbols, invalid files, exact round-trip of supported subset, frontend isolation from core.

## Acceptance criteria

Supported graphics subset round-trips exactly; transformation tasks use generic observation and Theory IR contracts; a new frontend compiles without modifying core crates; its independent verifier hook can be supplied when WP06 is present; adapter median is below 50 ms for moderate scenes.

## Forbidden shortcuts

Do not add graphics-specific effects to RKL when generic geometry and rendering suffice.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
