# WP30 — CPU vision frontend spike

## Objective

Measure whether classical and compact non-transformer CPU perception can supply useful uncertain REG evidence from natural images.

## Dependencies

WP29

## Owned scope

`frontends/vision`

## Inputs

A pre-registered small vision benchmark with segmentation, geometry, tracking, and relational questions.

## Deliverables

Image loader, edges/regions/contours/keypoints, candidate scene graph, uncertainty calibration, and benchmark report.

## Required design

Use classical CPU image processing first: color spaces, threshold families, edge detection, connected regions, contours, Hough-like lines, keypoint descriptors, template matching, and optional compact CPU convolutional/recurrent/state-space proposer behind a strict uncertainty interface. Keep raw image references and alternative detections.

## Public API obligations

Vision frontend implementation of WP29 contracts and detector plugin interface.

## Test plan

Lighting changes, noise, occlusion, repeated objects, false edges, resolution changes, corrupted files, deterministic classical path.

## Acceptance criteria

Pre-registered benchmark metrics met or an honest negative report; no GPU library loaded; inference fits declared CPU latency and memory; uncertain detections never treated as exact facts by verifier.

## Forbidden shortcuts

Do not claim general vision from a narrow spike. Do not download or call a remote vision model during answer generation.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
