# WP32 — Transformer-free text and knowledge frontend spike

## Objective

Provide a measured path for converting constrained text and documents into typed propositions and procedures without a transformer.

## Dependencies

WP23, WP29

## Owned scope

`frontends/text`

## Inputs

Pre-registered controlled-language, technical-document, and knowledge-retrieval suites.

## Deliverables

Tokenizer/morphology, chart parser, grammar and semantic frames, entity linking, proposition graph, source citations, and optional compact non-transformer ranker.

## Required design

Start with deterministic lexing, finite-state morphology, weighted context-free or combinatory parsing, typed semantic templates, coreference constraints, and source-aware knowledge graph insertion. Grammar induction may propose rules from examples. A small CPU recurrent, reservoir, or state-space model may rank alternatives but cannot fabricate facts or bypass source links.

## Public API obligations

Text frontend implementation, `Proposition`, `SourceSpan`, `ProcedureSchema`, `KnowledgeQuery`, and parse-forest artifact.

## Test plan

Ambiguous parses, negation, quantifiers, coreference, tables, conflicting sources, unknown terms, source-span replay, long-document streaming.

## Acceptance criteria

Meet pre-registered controlled-language exact semantic parse bar; every extracted fact has source span; contradictions coexist with provenance; no transformer dependency; benchmark result states unsupported natural-language scope explicitly.

## Forbidden shortcuts

Do not advertise unrestricted language understanding. Do not convert retrieval confidence into truth.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
