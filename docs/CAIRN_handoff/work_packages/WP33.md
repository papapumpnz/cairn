# WP33 — Benchmark harness, evidence packs, and gated evaluation

## Objective

Make every architecture claim reproducible, quarantined, and attributable.

## Dependencies

WP06, WP21, WP22

## Owned scope

`cairn-bench`, `cairn-eval`, experiment schemas

## Inputs

Solver, certificates, suite manifests, machine attestation.

## Deliverables

Task runner, JSONL metrics, report validator, confidence intervals, ablation runner, pre-registration templates, sealed eval workflow, and dashboard data.

## Required design

Write results incrementally and atomically. Validate configuration of record, task count, duplicate IDs, certificate replay, resource totals, terminal taxonomy, and baseline comparability. Compute pass@1/pass@2, Wilson intervals, overlap, timing percentiles, memory, and role attribution. Gate evaluation behind explicit sanction file and capability token; seal per-task diagnostics until summary committed.

## Public API obligations

`BenchRunner`, `RunManifest`, `TaskResult`, `BenchmarkResult`, `ReportValidator`, `EvalGate`, and CLI commands.

## Test plan

Interrupted run, duplicate result, corrupt certificate, missing task, wrong split, weakened threshold, inconsistent totals, resumed run, sealed diagnostics, benchmark contamination.

## Acceptance criteria

All report self-tests pass; one dummy suite reproduces byte-identical summary; verifier required for solved count; evaluation cannot run without sanction; standard evidence pack generated automatically; overhead below 2% of solve time.

## Forbidden shortcuts

Do not expose evaluation per-task outcomes to development processes. Do not use cost-normalized success without an absolute accuracy floor.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
