# WP33 — General-learning benchmark harness, evidence packs, and gated evaluation

## Objective

Report learning curves, invention provenance, actual/necessary mechanism reuse,
support expansion, search/sample/action reduction, negative transfer, and
forgetting. Solve rate alone is not a learning result.

Make all three learning loops and every architecture claim reproducible, quarantined, comparable, and attributable.

## Dependencies

WP06, WP23, WP28, WP29

## Owned scope

`cairn-bench`, `cairn-eval`, experiment schemas

## Inputs

Generic learner/runtime, certificates, three-domain suite manifests, memory snapshots, and machine attestation. ARC runners integrate later as adapters.

## Deliverables

Generic problem runner, GLL-1 through GLL-6 suites, JSONL three-loop metrics, memory/action ablations, report validator, confidence intervals, preregistration templates, sealed adapter-evaluation workflow, and dashboard data.

## Required design

Write results incrementally and atomically. Validate the configuration of record, problem count, duplicate IDs, certificate replay, resource totals, terminal taxonomy, and baseline comparability. Enforce the same frozen set and CPU budget for memory-on/off and active/random comparisons. Report demonstrations, hypotheses, search, interventions, transfer, regressions, accuracy, timing, memory, and role attribution separately for all three loops. Gate quarantined adapter evaluations behind an explicit sanction file and capability token.

## Public API obligations

`BenchRunner`, `RunManifest`, `TaskResult`, `BenchmarkResult`, `ReportValidator`, `EvalGate`, and CLI commands.

## Test plan

Interrupted run, duplicate result, corrupt certificate, missing problem, unequal ablation budget, changed frozen set, wrong split, weakened threshold, inconsistent totals, resumed run, sealed diagnostics, adapter contamination.

## Acceptance criteria

All report self-tests pass; memory and intervention ablations reject unequal budgets; one three-domain dummy suite reproduces byte-identical summaries; verifier is required for success; quarantined evaluation cannot run without sanction; standard evidence packs are automatic; overhead is below 2%.

## Forbidden shortcuts

Do not expose evaluation per-task outcomes to development processes. Do not use cost-normalized success without an absolute accuracy floor.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
