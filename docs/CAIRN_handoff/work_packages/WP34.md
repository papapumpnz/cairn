# WP34 — End-to-end integration, profiling, and release solver

## Objective

Integrate the static architecture into one anytime solver, profile the critical path, and run the pre-registered diagnostic ladder.

## Dependencies

WP18, WP19, WP20, WP21, WP22, WP24, WP33

## Owned scope

top-level `cairn` binary, integration configuration, release profiles

## Inputs

All static core crates, local swarm, ARC frontend, benchmark harness.

## Deliverables

Single-node and swarm solver binaries, staged budgets, checkpoint/resume, failure taxonomy, profiling reports, and X-style benchmark artifacts.

## Required design

Implement stages A through F from the master design. Use evidence fingerprints only to schedule general agents. Maintain task frontier, belief modes, stop criteria, and second-attempt budget. Profile allocation, entity generation, event cover, constraints, execution, invention, and verification. Optimize only measured bottlenecks through batching, caching, data layout, or micro-op compilation; preserve reference semantics.

## Public API obligations

`cairn solve`, `cairn suite`, configuration schema, stage checkpoints, and top-level `StaticSolver` implementation.

## Test plan

End-to-end synthetic suites, 60-task frozen diagnostic, timeout at every stage, resume, memory cap, one-worker versus swarm determinism, memory-off, invention-off, and verifier failure injection.

## Acceptance criteria

Complete F through T gates required for integration; R1.0 initial gate or honest negative report; median and p95 resource targets reported; no unclassified failure; all answers independently verified; release binary passes attestation.

## Forbidden shortcuts

Do not patch individual diagnostic tasks. Do not hide component failures behind legacy solver fallback.

## Mandatory operating constraints

- CPU-only and transformer-free. Run `cairn-check` before handoff.
- No ARC task IDs, full-grid hashes, memorized outputs, or task-family branches in production code.
- Deterministic semantic output for fixed input, semantics version, seed, and work budget.
- Canonical serialization for every persistent public type.
- Exact errors: distinguish invalid input, unsupported semantics, capacity cap, timeout, and internal defect.
- Add metrics before optimizing. A speed claim requires the naive or previous baseline on the same machine.
- No evaluation split access.

## Required handoff

Return a committed implementation, public API documentation, test commands, benchmark commands, evidence artifacts, acceptance-criterion table, known limitations, and the exact downstream interface tag.
