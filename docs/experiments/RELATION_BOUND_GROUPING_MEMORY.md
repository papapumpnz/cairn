# Relation-bound grouping memory experiment

Status: `PASS_WITH_DECLARED_LIMITS`

## Frozen question

Can CAIRN retain the jointly selected grouping relation and executable merge as
one proposal-only mechanism, earn promotion through independent reuse, and
reduce future learning work without storing source answers?

## Method

Two independently named cohorts span vector, sequence, table, and workflow
observations. Every episode supplies two equal-count relation partitions. Only
`structural-membership` supports one RKL max-minus-min aggregate. Cohorts vary
values, group counts, and group cardinalities. The online learner independently
invents both compositions.

The independent verifier selects the declared role, recomputes group evidence,
executes raw RKL, and checks unordered outputs. The consolidator receives two
disjoint receipts. A held-out graphics/operations cohort changes identities,
values, counts, and cardinalities. Blank memory and a changed relation identity
are ablations.

## Measured result

```text
independent learning cohorts: 2
promotion receipts: 2 disjoint
fresh candidate executions: 187
persistent proposal attempts: 1
fresh examples / reuse examples: 4 / 0
held-out groups independently replayed: 9 / 9 exact
blank-memory proposals: 0
duplicate receipts admitted: 0
changed-relation certificate applications: 0
```

## Interpretation

This establishes that future search changes because the selected relation and
aggregate are retained together. It does not establish raw relation generation:
both candidate roles are still supplied by a frontend. Persistence currently
means proof-gated process memory; canonical CAS serialization and restart replay
remain open. No ARC measurement or general-intelligence claim follows.
