## Correctness and determinism

Reference implementation comparison: `PromotionVerifier` re-executes the
checked collection theory; storage never performs semantic verification.

Checkpoint/resume comparison: fresh receipts and restart-reconstructed receipts
produce the same promotion outcome.

Cross-process deterministic replay: simulated by process-local receipt loss,
CAS reopen/recovery, and metadata-independent semantic identity.

Canonical serialization round trip: typed payload → envelope → CAS → bounded
canonical value → typed payload.

Independent verifier result: two reconstructed opaque receipts accepted;
changed theory, output, and metric claims rejected.

## Known limits

- Counterfactual measurements must be freshly produced by the experiment
  runner; WP23 does not place the solver inside the independent verifier.
- The archive currently covers procedural collection reuse receipts, not every
  scalar `ReuseEvidence` path.
- Parent lineage presence is enforced, but complete parent-graph traversal is
  still an orchestrator/CAS-manifest responsibility.
- No wall-clock speed claim is made; the gate uses deterministic work counts.
- Proof graph parent presence is checked, but complete parent-graph traversal
  remains a manifest/orchestrator responsibility.
- Internal mining covers connected contiguous topological windows only, not
  arbitrary non-contiguous subgraphs or graph-edit alignment.
- Internal proposals are exact proof patterns, not yet compiled executable RKL
  mechanisms, persisted modules, or promotion certificates.
- No ARC rerun is attributed to this milestone because it does not enter the
  ARC answer path; the last measured frozen result remains 36/400.
